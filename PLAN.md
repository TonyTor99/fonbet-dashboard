# Fonbet Dashboard — план веб-панели аналитики

Панель для анализа/бэктеста данных бота fonbet-ipbl по всем 8 БД. Веб, без установки клиенту,
крутится на VPS рядом с ботом, обновление данных по кнопке.

## 2. Модель расчёта (общая для всех источников)

- **Банкролл:** флэт. Банк = 100 000. Ставка = фикс (по умолчанию 1% = 1000), настраивается.
- **Профит ставки:** Выигрыш → `(odds-1)*stake`; Проигрыш → `-stake`; Возврат → `0`.
- **Метрики:** прибыль (ед. и % от банка), оборот (Σ ставок), ROI = прибыль/оборот·100,
  число ставок, число матчей, винрейт %, средний кф, макс. просадка (ед. и %), макс. серия проигрышей.
- **График:** кумулятивная кривая прибыли по дате ставки. Таблица всех ставок с деталями.

## 3. Логика «ставки» по типам

### market_snapshots (рынки, поминутно) и period_snapshots (четверти)
На матч десятки снимков → нужен **параметризуемый вход** (выбор исхода + момента):

1. **Исход/рынок** (выбор): ТМ, ТБ, Ф1, Ф2, ИТ1Б, ИТ1М, ИТ2Б, ИТ2М, П1, П2.
   Для хоккея дополнительно: X (ничья), 1X, 12, X2. Для четвертей: П1/X/П2.
   Каждый исход = пара колонок (котировка + результат `r_*`).
2. **Момент входа** (выбор):
   - Предматч (`game_minute=0` / `is_prematch=1`);
   - Минута N или диапазон минут (баскетбол — сквозная минута, до ~57);
   - Четверть/период N (баскетбол `quarter`, хоккей `period`).
3. На каждый `event_id` берём **первый снимок**, удовлетворяющий {момент + кф в диапазоне} → 1 ставка.
   Результат = `r_<исход>` этого снимка. Нет подходящего снимка → матч пропущен.

### signals (ipbl.db) — готовые ставки, отдельный адаптер
Фильтры под специфику: `strategy` (signal_tm/prime_info), `division` (pro/prime), `status`
(по умолчанию — реально отправленные `sent`, опц. включить остальные), `muted`, `qualified`,
диапазон `odds`, лига, даты. Профит считаем сами из `odds`+`result` (в БД он пуст).

## 4. Фильтры панели (общие)

- Диапазон котировок (min..max выбранного исхода).
- Чемпионат / лига (мультивыбор из `league`; для хоккея — 7 лиг).
- Игровая минута / четверть / период.
- Календарный период (даты `created_at` / `snap_dt_msk`).
- Тип рынка / исход (см. п.3).
- Размер ставки и банк (для метрик).

## 5. Архитектура

- **Backend:** FastAPI (используем существующий python/venv стиля бота). Читает snapshot-БД
  только на чтение. Единый backtest-движок + конфиг-адаптеры на каждый источник
  (файл, таблица, маппинг исход→колонки, доступные моменты входа, лиги).
  - `GET /api/sources` — список источников и их возможностей (рынки, лиги, диапазон дат).
  - `POST /api/backtest` — фильтры → метрики + кривая + список ставок.
  - `POST /api/refresh` — на сервере делает `sqlite3.backup` боевых БД бота в рабочую папку панели
    (безопасно, без нагрузки на бота), возвращает время обновления. Локально — no-op/из snapshots.
- **Frontend:** React (Vite), собирается в статику, отдаётся тем же FastAPI (один процесс/порт).
  Слева панель фильтров, сверху карточки метрик, центр — график прибыли, снизу таблица ставок.
- **Один процесс, один порт** (напр. 8080). Локально: `uvicorn`, читает `snapshots/`.
